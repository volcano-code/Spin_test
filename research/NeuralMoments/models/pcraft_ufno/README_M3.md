## Conditional fairness and limitations

`faircut_m3.py` runs **all three real PyTorch architectures**, no neural-generated
labels. For each seed (19, 23, 29): same exact W0-native-cut analytical oracle,
same 8^3 raw voxels, same 40 *distinct* train geometries (20 boxes, 20
spheres), 80 train queries, 20 heldout ellipsoids, 40 heldout queries;
identical seeded minibatch schedule, 12 Adam steps at lr 0.003, batch 8,
MSE(r) versus MSE(r)+0.5 MSE(J). No cross-family/geometry-ID leakage.
Models use 13,982 (UFNO), 13,674 (DeepONet) and 13,482 (GeometryMLP)
trainable **real scalar** parameters, within 5% capacity.

**Representation parity is NOT fully satisfied:** W6 directly receives all
four voxel channels; original W5 models expect 9 scalars. W5 is instead fed a
fixed no-label, no-family-identity 9D summary extracted solely from exactly the
same 4-channel voxel geometry (density fraction, centroid, variance, two
covariances). This deterministic descriptor is **lossy** and has no trainable
parameters. We do **not** use original W5's privileged primitive one-hot,
exact center or exact semiaxes. Cold W5 timing includes descriptor extraction.
Results are conditional on that feature policy, NOT a final neural-operator
ranking and certainly not a full-input-equivalent contest.

One shared `ResidualAdapter` for 0/1/2 independent analytic teacher queries is
used across all three models (not W5's different native ridge adapter).
Warm timings exclude geometry encoding for all. Cold timings start with the
same voxel tensor; CPU threads=1, no CUDA. Runtime CPU peak process RSS is not
phase- or model-only VRAM. Saved training labels include continuum J; actual
Cherchi teacher derivatives may have extra cost and invalid states. Their
future query/time budgets must be charged from W2 measurements.

## Reproduce actual local execution

From the **repository root**, with Python 3.10+, PyTorch 2+, NumPy:

```bash
python -m unittest research.NeuralMoments.models.pcraft_ufno.test_faircut_m3 -v
python -m research.NeuralMoments.models.pcraft_ufno.m3_multiseed \
    --seeds 19,23,29 --steps 12 --per-family 20 --grid-size 8 --repeats 5 \
    --output research/NeuralMoments/models/pcraft_ufno/m3_full_local.json
```

The exact local regression returned **13 passed / 1.688 seconds** on
PyTorch 2.10.0+cpu; log `m3_test_local.log` is committed. Three complete
seed runs actually executed. The GitHub-visible **compact** results and
per-seed dataset/batch SHA-256 manifests are saved in
`m3_summary_seed19_23_29.json` (full raw per-timing/seed JSON was produced
locally and can be regenerated by the command above). This is a true local
run, **not** a claim of GitHub CI or production native execution.

## Scientific results (three seeds; mean ± sample SD)

| Model, both r and J supervised | Raw r MAE ↓ | Raw J MAE ↓ |
|---|---:|---:|
| W6 UFNO | 0.07765 ± 0.01343 | 0.02340 ± 0.00252 |
| W5 DeepONet | 0.06961 ± 0.00452 | **0.02256 ± 0.00083** |
| W5 Geometry-MLP | **0.05518 ± 0.01468** | 0.02398 ± 0.00153 |

The previous W6 M2 had an additional smooth `Jq` regularizer. Here this is
intentionally **disabled in all models** so the supervised losses match; M2
and M3's enhanced-arm numbers should not be conflated. The separate
moment-only arms and detailed scores are in the committed JSON.

In the enhanced arm the median-of-three CPU cold voxel-to-head times were
~2.2 ms W6, 0.24 ms DeepONet, 0.20 ms Geometry-MLP; warm cached head
~0.064, 0.037, 0.024 ms respectively. This is measured on one CPU host,
not a hardware-normalized GPU comparison or Faster acceleration proof.
All three models saturated the single-case norm-capped synthetic optimization
step; zero step-error is therefore **not** evidence of good decision quality.
The report includes uncapped physical-objective gradient errors as a more
revealing but still synthetic diagnostic. No optimization convergence proven.
